# АВИ - Академия Водных Искусств

Лендинг для Академии Водных Искусств.

## Структура проекта

```
src/
├── assets/
│   ├── img/                # Изображения
│   ├── fonts/              # Шрифты
│   └── sprite/             # SVG спрайты
├── styles/
│   ├── base/
│   │   ├── _vars.scss      # CSS переменные
│   │   └── _reset.scss     # Базовые стили и сброс
│   ├── components/
│   │   ├── buttons/
│   │   │   └── _btn.scss   # Компонент кнопки
│   │   └── forms/          # Компоненты форм
│   ├── extends/            # SCSS расширения
│   ├── mixins/             # SCSS миксины
│   └── main.scss           # Главный SCSS файл
├── pug/                    # Pug шаблоны (будущее)
├── js/
│   └── main.js             # Главный JS файл
└── index.pug               # Главная Pug страница
```

## Запуск проекта

```bash
npm run dev      # Запуск dev сервера
npm run build    # Сборка проекта
npm run preview  # Предпросмотр сборки
```

## Технологии

- Vite + Vituum - сборщик
- Pug - шаблонизатор
- SCSS - препроцессор CSS
- SVG Spritemap - спрайты иконок
- Vanilla JavaScript

- Горячая перезагрузка
- Современный ES6+ JavaScript

Workflow [«Сборка и публикация Nova Swim»](https://github.com/YuriyBevov/nova-swim.ru/actions/workflows/site.yml) при pull request проверяет и собирает проект. Push в `main` после успешных проверок загружает сборку по SSH. Повторный запуск доступен через **Actions → Сборка и публикация Nova Swim → Run workflow**. Node.js и npm нужны только на runner; на сервер загружаются готовые файлы, PHP и PHPMailer.

Перед обновлением создаётся полный архив публичной папки. Деплой сохраняет `cgi-bin` и файлы хостинга, не использует `rsync --delete`, публикует `index.html` последним и восстанавливает прежние файлы при ошибке копирования. Публикации выполняются последовательно; устаревший коммит `main` не разворачивается. Архивы сохраняются в `backups` без автоматического удаления — периодически проверяйте объём.

В **Settings → Secrets and variables → Actions → Variables** используются:

| Переменная | Значение |
| --- | --- |
| `DEPLOY_HOST` | `5.23.50.132` |
| `DEPLOY_PORT` | `22` |
| `DEPLOY_USER` | `cu10219` |
| `DEPLOY_ROOT` | `/home/c/cu10219/nova-swim/public_html` |
| `DEPLOY_STATE` | `/home/c/cu10219/.deploy/nova-swim` |
| `PRODUCTION_DEPLOY_ENABLED` | `true`; значение `false` отключает публикацию, сохраняя проверки |

Секреты `DEPLOY_SSH_PRIVATE_KEY` и `DEPLOY_SSH_KNOWN_HOSTS` содержат отдельный SSH-ключ Nova Swim и проверенную запись хоста. Ключи соседних проектов в этот репозиторий не передаются. SMTP-пароль в GitHub не нужен. См. [документацию GitHub по секретам Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

Домен подключается отдельно в панели Timeweb к сайту `nova-swim`; после настройки DNS необходимо выпустить HTTPS-сертификат. CI/CD не меняет DNS и привязку доменов.

### Настройка почты для заявок

1. Создайте почтовый ящик у выбранного почтового провайдера, например `info@nova-swim.ru`. Включите SMTP-доступ и, если провайдер требует, создайте пароль приложения. Для доменной почты добавьте DNS-записи MX, SPF, DKIM и DMARC по инструкции этого провайдера.
2. Откройте на сервере **`/home/c/cu10219/nova-swim/shared/mail-config.php`**. Этот файл находится вне `public_html`, не попадает в Git и сохраняется при каждом деплое. Шаблон без пароля: `deploy/mail-config.example.php`.
3. Замените настройки в следующем массиве:

   ```php
   <?php
   return [
       'smtp' => [
           'host' => 'smtp.ВАШ-ПРОВАЙДЕР.ru',
           'username' => 'info@nova-swim.ru',
           'password' => 'ПАРОЛЬ_ПРИЛОЖЕНИЯ',
           'secure' => 'ssl',
           'port' => 465,
       ],
       'from' => [
           'email' => 'info@nova-swim.ru',
           'name' => 'Nova Swim',
       ],
       'recipients' => [
           'info@nova-swim.ru' => 'Администратор Nova Swim',
           // 'manager@example.com' => 'Менеджер',
       ],
       'allowed_origins' => [
           'https://nova-swim.ru',
           'https://www.nova-swim.ru',
       ],
   ];
   ```

   | Где менять | Что указать |
   | --- | --- |
   | `smtp.host` | SMTP-сервер из настроек почтового провайдера |
   | `smtp.username` | Обычно полный адрес ящика отправителя |
   | `smtp.password` | Пароль приложения или SMTP-пароль |
   | `smtp.secure`, `smtp.port` | `ssl` + `465` или `tls` + `587`, согласно настройкам провайдера |
   | `from.email` | Адрес отправителя, разрешённый провайдером; обычно совпадает с `smtp.username` |
   | `from.name` | Имя отправителя, видимое в письме |
   | `recipients` | Адреса, **на которые приходят заявки**; можно добавить несколько строк |
   | `allowed_origins` | Точные адреса сайта со схемой `https://`, без завершающего `/`; дополнить, если будет другой домен |

4. Проверьте синтаксис и права доступа по SSH:

   ```sh
   php -l /home/c/cu10219/nova-swim/shared/mail-config.php
   chmod 700 /home/c/cu10219/nova-swim/shared
   chmod 600 /home/c/cu10219/nova-swim/shared/mail-config.php
   ```

5. После подключения домена и HTTPS отправьте одну заявку через форму и убедитесь, что письмо пришло получателям, включая папку «Спам». Пересборка и повторный деплой после смены SMTP-пароля не нужны. Шаблон SMTP основан на [настройках PHPMailer](https://github.com/PHPMailer/PHPMailer/blob/master/examples/smtp.phps).

До заполнения SMTP-настроек обработчик возвращает HTTP `503`, а форма показывает ошибку. При сбое доставки возвращается `502`; сообщение об успехе показывается только после успешной отправки. Подробные SMTP-ответы, пароли и данные заявки в браузер не возвращаются. В PHP-журнал попадает только статус вида `Nova Swim mail: exception` или `success`; размещение и просмотр PHP-журналов зависят от настроек сайта в панели Timeweb.

При проблемах проверьте пароль приложения, SMTP-доступ, соответствие порта и шифрования, адрес отправителя и возможность исходящего соединения к SMTP-порту. Проверка TLS-сертификатов включена. Обычный GET-запрос к `/mail.php` возвращает `405` — обработчик принимает только POST, это штатное поведение.

Адрес `info@nova-swim.ru`, видимый в шапке, меню, подвале и политике, меняется отдельно в `src/pug/layouts/header/tpl.pug`, `src/pug/components/nav/tpl.pug`, `src/pug/layouts/footer/tpl.pug` и `src/pug/components/modals/policy-modal/tpl.pug`; эти изменения публикуются через `main`.

### Резервные копии и восстановление

До каждой публикации текущая папка сохраняется в `/home/c/cu10219/.deploy/nova-swim/backups/<релиз>.tar.gz`. При необходимости восстановления сначала установите `PRODUCTION_DEPLOY_ENABLED=false`, чтобы автоматическая публикация не перезаписала восстановленные файлы. Список архивов:

```sh
ls -lt /home/c/cu10219/.deploy/nova-swim/backups
```

Для обычного отката к прежнему коду предпочтительно выполнить `git revert` нужного коммита в `main`: GitHub проверит и опубликует новую сборку. Для восстановления точной копии папки используйте выбранный архив; сначала сохраните текущее состояние. SMTP-настройки находятся вне архивируемой публичной папки и не откатываются.
